## 4. 打包 / 解析流程（tavern-cards-forge CLI）

命令统一（**workdir 必须是 `D:\写卡测试\cards`**）：

```
node "C:\Users\Administrator\.dsh\tavern-cards\tavern-cards\scripts\tavern-cards-forge.mjs" <cmd> 天启预报
```

子命令：`pack` / `unpack --file <png> --output <dir> --json --fresh` / `patch --file <patch>` / `configure` / `validate-mvu` / `query <jsonpath>` / `export` / `split` / `init`。

###  PNG 是容器
- 看卡数据用 `forge unpack --json`，不要用读图工具；`read_image` 看 PNG 卡只能看到封面。
- unpack 出来的关键字段：`first_mes`、`regex_scripts[*].replaceString`、`character_book.entries[*]`、`character_version`、`data.extensions`。

### 版本号三处同步（改版本时都要改）
1. `tavern-cards-state.json` 的 `version`。
2. `tavern-cards-state.json` 的 `worldbookName`。
3. pack 输出文件名（`--output cards/天启预报/天启预报X.png`）或 `.cardrc.json` 的 artifact。

## 5. 灯色与 token

| 灯色 | strategy.type | 何时注入 | 占常驻 token |
|---|---|---|---|
|  蓝灯 | `constant` | 每轮都发 | 是 |
|  绿灯 | `selective` | 正文/最近消息命中 keys 才发 | 否 |
|  关 | `null` / 无 strategy | 永不发 | 否 |

- 灯色在 `tavern-cards-state.json  entryManifest  <条目>.strategy`。
- 蓝灯改绿灯：`"strategy": { "type": "selective", "keys": [...] }`（keys 必填）；绿改蓝删 keys。
- 约定：规则类（世界观/扮演准则/时间线）默认蓝灯；参考类（地理/角色/NPC/事件）默认绿灯。
- token 估算（实测口径）：Gemini 中文约 1.29 字符/token（含换行；不含换行约 1.216），世界书 YAML 含大量 ASCII 标点/数字/英文标签，比纯中文更省，所以 1.29 是蓝灯上界，做保守测算用它。1.7.9 蓝灯约 3.0 万字符 ≈ 2.3 万 token；场景示例（新海+石髓馆+槐诗+第1幕）约 4.1 万字符 ≈ 3.2 万 token。

## 6. 核心约定（铁律）

1. **灯色铁律**：规则类蓝灯 constant，参考类绿灯 selective。`Infinity`=constant，`0`=selective，`null`=disabled。
2. **seg 禁令**：世界书内禁止 `seg_XX` 编号、禁止资料库路径，只写「第X幕/幕名/角色名」（正文 AI 没有 seg 概念）。
3. **资料库 vs 世界书**：资料库是权威设定，别的 AI 只更新资料库；世界书是工作区，只有本会话改。
4. **自包含**：卡内容必须自包含，正文 AI 拿不到资料库。
5. **UTF-8 无 BOM**：JSON/YAML 必须无 BOM（pwsh 写用 `[System.Text.UTF8Encoding]::new($false)`）。
6. **新建世界书条目不会自动进 entryManifest**：要手动编辑 `state.json`（forge 没有 scan）。
7. **更新笔记约定**：每次版本升级追加 `更新笔记.md` + 在对话里展示给用户。

## 7. 关键设计决策（勿随意推翻）

- **阶位档值**：线性 `不入阶0/应激1/发育2/水银3/黄金4/以太5/星锑6/贤者之石7/天敌8`；数字阶名先映射名词（一阶=水银、二阶=黄金、三阶=以太、四阶=星锑、五阶=贤者之石）。
- **圣痕**：谱系路径阶段称谓；两态（日常=静默态痕迹，激发=催动源质后的异象，都不是能力）；只有晋升成功才更新（remove 旧 insert 新）；技能不因圣痕替换消失。
- **技能**：主动（消耗源质/发动负荷>0）+ 被动（消耗全 0、常驻日常效果）；获得圣痕生成 1 主动 + 1 被动。
- **灵魂能力**：个人灵魂本质展开；玩家开局不可获得，完成伟业后觉醒；1-5 阶，三个同阶合成高一阶。
- **称号**：只增不删；1-5 阶；称号名 2-6 字、效果 15 字。
- **破阶许可**：源质武装破阶标签/威权/已知克制/暴露弱点/陷阱束缚仪式/合法临时阶位。
- **好感度**：-200~200，9 阶段。
- **晋升仪式**：玩家发翠玉录咒语 = 仪式已完成，AI 只生成两个仪式方向，禁止再输出仪式要求清单。
- **危险度枚举**：平静/紧张/危机/濒临毁灭（开局默认平静）。

## 8. 踩过的坑（务必避免）

1. **`<script>` 和内联 `onclick` 会被 DOMPurify 移除**：正则 replaceString 用 ```html 围栏 + 完整 HTML 文档 + IIFE + addEventListener。
2. **围栏必须带 `html` 标记**，否则显示字面围栏。
3. **replaceString 里别写字面尖括号标签**（`<UpdateVariable>`、`<StatusPlaceHolderImpl/>` 等），会被卡内正则误匹配吞 script。
4. **开场白用 `.md` 后缀**，避开 forge 自动追加 `<StatusPlaceHolderImpl/>`。
5. **schema 字段尽量 union/预处理兼容**，别假设 AI 会写对类型（技能消耗、里程碑条件、圣痕字符串、称号名等）。
6. **MVU 变量不参与世界书关键词扫描**：变量值必须在文本里也出现一次。
7. **数字阶名必须映射名词后再写变量**（尤其 NPC），否则 schema 兜底「不入阶」1.7.8.3 已修。
8. **read_image 看 PNG 卡只能看到封面**：要 unpack。
9. **patch 里 `move`+`replace` 不能同文件**：用 `remove`+`add`。
